## 1. 设计基准

| 项 | 规格 |
|---|---|
| 设计分辨率 | 1920 × 1080（横屏，16:9） |
| 虚拟像素基准 | **640 × 360**；1920×1080 为 3× 整数缩放，1280×720 为 2×，2560×1440 为 4× |
| 像素单位 | 1 个美术像素 = 虚拟基准下的 1px；禁止半像素、禁止非整数缩放 |
| 放大方式 | 整数倍最近邻（Point / Nearest），保持像素锐利 |
| 适配 | 整数缩放 + 黑边/安全区；超宽屏（20:9）左右留空，不拉伸像素 |
| 最小可读尺寸 | 1280 × 720（2×） |
| 纹理过滤 | **Point**；关闭 mipmap；关闭纹理压缩（避免色块和边缘损坏） |
| 颜色空间 | sRGB |
| 透明通道 | PNG straight alpha；禁止预乘；禁止半透明抗锯齿边缘（除非刻意表现光效） |

> **混合分辨率原则**：精灵、背景、UI 边框走像素网格；中文正文用系统字体在原生分辨率渲染。不要把中文正文做成像素字，640×360 下会不可读。

## 2. 像素风规范

### 2.1 风格方向

- 16-bit / 32-bit 时代的 Q 版像素：轮廓清晰、色块干净、动作夸张但可读。
- 每个宠物一套**受限调色板**（32~48 色），全 UI 共用一套基础色板。
- 1px 深色描边（不用纯黑，用深蓝/深棕），光源统一为左上。
- 不做渐变噪点、不做高分辨率笔刷、不做抗锯齿。

### 2.2 原则

- 原创 IP，不使用任何已有作品的形象、名称、配色组合。
- 元素用“颜色 + 图标”双重编码，照顾色弱。
- 战斗图优先保证**剪影和动作可读性**，细节让位于辨识度。
- 不把文字烘焙进图片；所有文案走 `Label`，便于后续多语言。
- 同一只宠物在不同动作里保持调色板、描边和比例一致。

### 2.3 像素网格

- 所有精灵按基础尺寸绘制，导出时不缩放；运行时整数倍放大。
- 禁止旋转非 90° 的精灵；禁止亚像素位移；UI 动效可以平滑，但精灵本身保持像素对齐。
- 图集内精灵坐标必须为整数；pivot 对齐到像素。

| 按钮 | 主/次/危险/图标按钮，normal/pressed/disabled | 12~20 |
| 条 | HP、精力、经验、状态 | 4~6 |
| 图标 | 货币、资源、属性、状态、技能类型 | 20~30 |
| 框架 | 稀有度、选中、锁定、标签 | 6~10 |
| 控件 | Tab、滑条、开关、分页、滚动条 | 8~12 |
| 装饰 | 标题、角标、分割线 | 5~10 |

### 3.3 场景

| 资源 | 数量 | 说明 |

## 4. 尺寸与格式

### 4.1 宠物

| 资源 | 基础尺寸 | 运行时缩放 | 格式 | 备注 |
|---|---|---|---|---|
| 标准战斗精灵 | 96 × 96 | 3× = 288px | PNG | pivot 底部中心 |
| 小型宠物 | 64 × 64 | 3× = 192px | PNG | 同一套动作 |
| Boss/大型 | 128 × 128 | 3× = 384px | PNG | 同一套动作 |
| 立绘 | 256 × 256 | 3× = 768px | PNG | 详情/图鉴 |
| 头像 | 48 × 48 | 3× = 144px | PNG | 列表/编队 |
| 小图标 | 32 × 32 | 3× = 96px | PNG | 战斗头像/图鉴 |
| 蛋 | 48 × 48 | 3× = 144px | PNG | 按物种 |

> 96×96 是**基础像素画布**，不是显示尺寸。显示时整数倍放大，保持锐利。

### 4.2 UI

| 资源 | 基础尺寸 | 格式 | 备注 |
|---|---|---|---|
| 通用 UI 图集 | 1024 × 1024（优先）/ 2048 × 2048 | PNG | 9-slice 面板、按钮、条 |
| 图标 | 16 / 24 / 32 | PNG | 按使用场景 |
| 背景 | 640 × 360 | PNG | 3× 放大；禁止 JPG（块状伪影） |
| 特效帧 | 32 / 64 | PNG | 按需 |

### 4.3 音频

| 资源 | 格式 | 码率 | 备注 |
|---|---|---|---|
| BGM | MP3 | 96~128kbps | 循环点标注 |
| SFX | MP3 | 64~96kbps | 短音效，≤2s |

> 微信小游戏与 Steam 都优先 MP3；Steam 如需更高音质可另用 OGG，但保持一套资源更省心。

### 4.4 图集

- 优先 1024×1024；最大 2048×2048；2 的幂；2px padding。
- 关闭纹理压缩、关闭 mipmap；导入过滤设为 Point。
- 不要把不同缩放/不同调色板的资源塞进同一图集。
- UI 图集与宠物图集分开；宠物按单只或小组打包，便于按需加载。
- 开启 trim 时必须保留原始 pivot 元数据；像素精灵不建议自动旋转。

## 5. 动画

### 5.1 方案

| 方案 | 适用 | 说明 |
|---|---|---|
| **序列帧（Aseprite）** | 宠物战斗、特效 | **MVP 首选**；像素风一致、可控 |
| Cocos Tween | UI、飘字、血条 | 代码驱动，不占美术资源 |
| Spine / DragonBones | 不推荐 | 骨骼变形会破坏像素网格，风格不统一 |

**决策**：宠物用 Aseprite 序列帧，导出 PNG 精灵表 + JSON（帧、时长、pivot）。不做 Spine。

> Cocos 不原生识别 Aseprite JSON。M0 先验证导入链路：自写转换脚本生成 SpriteFrame/AnimationClip，或直接导出 PNG 序列帧在 Cocos 里建动画。不要等量产才发现。

### 5.2 帧率与帧数

| 动作 | 帧率 | 帧数 | 循环 |
|---|---|---|---|
| idle | 8~12fps | 4~6 | 是 |
| attack | 8~12fps | 4~6 | 否 |
| hit | 8~12fps | 1~2 | 否 |
| faint | 8~12fps | 3~4 | 否 |
| sleep | 8fps | 2 | 是 |
| happy | 8~12fps | 3~4 | 否 |

- 2 倍速 = 播放速度 ×2；跳过 = 直接消费事件到终态。
- 精灵不做亚像素位移；需要位移时按整数像素。
- 特效不遮挡血条和技能栏。

## 6. 命名规范

```
pet_{species}_{element}_{action}.png
pet_{species}_{element}_{action}.json      # Aseprite 帧数据
  例：pet_turtle_water_idle.png / .json

pet_{species}_{element}_portrait.png
pet_{species}_{element}_icon.png
pet_{species}_egg.png

ui_{category}_{name}_{state}.png
  例：ui_button_primary_normal.png
      ui_bar_hp_fill.png
      ui_icon_element_water.png

bg_{scene}_{variant}.png
  例：bg_habitat_water_day.png

fx_{name}_{index}.png
  例：fx_hit_slash_00.png

sfx_{name}.mp3
bgm_{name}.mp3
```

- 全小写、下划线分隔、无中文、无空格。
- 状态后缀：`normal / pressed / disabled / selected / locked`。
- 元素：`water / fire / grass / earth / thunder`。
- 物种：`turtle / fish / frog / cat / snake`。
- 帧索引补零两位：`_00`、`_01`。

## 7. 包体预算

### 7.1 微信小游戏

| 项 | 内部预算 | 说明 |
|---|---|---|
| 主包 | ≤2MB | 官方上限 4MB；Boot/Home/Habitat/通用 UI/3 只初始宠物 |
| 宠物分包 | ≤4MB | 精灵表，按需加载 |
| 立绘分包 | ≤4MB | 详情/图鉴 |
| 音频分包 | ≤3MB | BGM + SFX |
| 总资源 | ≤15MB | 内部预算；官方上限以最新规则为准 |

### 7.2 单资源预算

| 资源 | 预算 |
|---|---|
| 单只宠物全套精灵表 | ≤60KB（PNG-8） |
| 单只宠物立绘 | ≤100KB |
| 头像/图标 | ≤5KB |
| 通用 UI 图集 | ≤500KB |
| 背景 | ≤100KB/张 |
| BGM | ≤1MB/首 |
| 单 SFX | ≤30KB |

### 7.3 Steam

- 像素资源本身很小，首包主要受音频/立绘影响，目标 <500MB。
- 同一套像素资源在 4K 下用 4× 整数放大，不单独做高分辨率重绘。
- 桌面端可增加 UI 密度和 tooltip，不改变像素资产。

## 8. 交付与验收

### 8.1 交付物

- `.aseprite` 源文件 + 导出的 PNG 精灵表 + JSON。
- 调色板文件（`.pal` / `.gpl`）。
- 图集清单、帧序列清单、循环点、pivot 说明。
- 命名符合 §6。
- 导入设置说明：Point、无压缩、无 mipmap、整数缩放。

### 8.2 验收清单

- [ ] 整数缩放，无模糊/拉伸
- [ ] 无抗锯齿、无半透明边缘（光效除外）
- [ ] 调色板一致，描边 1px，光源统一
- [ ] 精灵 baseline/pivot 对齐，动画无抖动
- [ ] 图集 2px padding，无溢出/串色
- [ ] 9-slice 拉伸不变形
- [ ] 文字未烘焙进图片
- [ ] 元素色 + 图标双重编码
- [ ] 1280×720（2×）与 1920×1080（3×）下清晰
- [ ] 文件命名正确
- [ ] 压缩后体积在预算内
- [ ] sRGB，无异常色偏

### 8.3 占位图策略

- 用**基础尺寸的色块 + 1px 描边 + 文字标签**做占位，按整数倍放大。
- 占位图必须保持 pivot、尺寸、锚点与最终资源一致，方便替换。
- 先用占位图跑通 UI 布局和战斗演出，再进入量产。

## 9. 生产顺序

1. **M0**：像素风样张（水龟）、全局调色板、UI kit、Aseprite 导出/导入流程、占位图。
2. **M1**：3 只初始宠物、栖息地背景、通用 UI、基础特效/音效。
3. **M3**：剩余 MVP 宠物、立绘、战斗背景、BGM、稀有度框架。
4. **M4（Steam）**：桌面 UI 密度、成就图标；像素资产复用，不重绘。
5. **后续**：25 组合全量、装饰、活动主题。

> **不要先量产再改玩法**。M0 的样张和 UI kit 必须先把像素网格、尺寸、动效、信息密度定死。
