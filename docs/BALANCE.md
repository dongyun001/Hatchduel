### 2.1 技能节奏（P-002）

- 小技能 45~50、大招 70~80，回合 +20、普攻命中 +10：全程普攻时第 3 回合可放大招，
  每 3 回合一次；大招后从 ≤10 重新攒。
- 本轮 sim 的玩家策略会为大招留能量，所以**小技能实际释放密度为 0**（满足 < 0.5）；
  这不是“小技能没用”，而是能量取舍很尖锐：每放一次 45~50 的小技能，大招就推迟约 1.5 回合。
- core 的贪心 AI 相反：有 45 能量就放小技能，几乎攒不到 70+。实测 30 场里 `fire_blaze`
  只放了 13 次、`dotTick` 3 次。见 §7：建议 A 给自动战斗 AI 加“留能量”策略，
  否则玩家开自动看不到大招。

### 4.1 五关配置（0.3.0）

| order | 关卡 | 敌方（物种/属性/Lv/基因/特质） | 首通经验 | 重复经验 | 首通资源 | 预期玩家 Lv |

| 2 | 泥岸冲突 | 龟/土/3/41；蛙/草/3/42；鱼/水/4/44 | 50 | 16 | 火猫 + 150 金币 + 8 尘 | 4 |
| 3 | 草丛伏击 | 猫/火/5/44；蛙/草/5/45；龟/水/6/48/强健 | 60 | 20 | 180 金币 + 20 食物 + 10 尘 | 5 |
| 4 | 毒牙沼泽 | 蛇/土/7/50；鱼/水/7/52/轻快；蛙/草/8/52 | 70 | 23 | 土蛇 + 220 金币 + 12 尘 | 7 |

- 第 1 关保持 2 敌人（core 的 `buildEnemyTeam` 快照锁定）；胜率 0.987，平均 3.70 回合。
- 第 2 关从 6/6/7 级别降到 3/3/4，胜率 0.611；龟不再带“强健”，改用基因质量拉开曲线。
- 第 3 关把「蛇/土」换成「蛙/草」，避免三个敌人全是伤害型群体大招（旧版胜率 0.007）；

- 第 4 关以蛇/鱼/蛙组成，**蛙 Lv8 治疗**是主要延长手段；胜率 0.371。

**死循环/负收益检查（静态 + 7 天曲线）**

- 食物：满容量净 +4.4/h；心情 0 时产出仍有 `6×1.4×0.8=6.72/h` > 维护 4/h，
  所以饥饿惩罚在当前配置下**不会触发**；它是提高消耗时的保险丝。
- 金币：基础 +16.8/h；喂养 4 只约 4.8 金币/h，净正。不喂养时 7 天仍 +2145 金币。
- 繁殖是主要金币/食物出口：按 2h 冷却连刷约 -50 金币/h，需要靠关卡重复奖励补；
  这是设计上的主动支出，不是死锁。
- 基因尘：产出 1.4/h + 五关 53 + 放生；2 级 20、3 级 60，均可达到。
- 7 天曲线（不喂养）：金币 2445、食物 621、基因尘 173；无负值、无 NaN；
  24h 单次推进产出是 8h 的 0.933 倍，说明 `offlineCapMs` 生效（不是 3 倍）。

## 5. 繁殖预期与结果

| 项 | 值 | 来源 |
|---|---|---|
| 物种 | 父母 50/50 | DOMAIN §8.2 |
| 属性 | 父母 50/50，1% 突变到任意属性 | `mutation.elementChance` |
| 数值基因 | 父母均值 + Irwin–Hall(σ=8)，四舍五入并 clamp 0~100 | `mutation.geneSigma` |
| 特质突变 | 每次繁殖 3%（近亲 +2%） | `mutation.traitChance` |
| 性别 | 50/50 | DOMAIN §8.2 |
| 代数 | `max(父母)+1` | DOMAIN §8.2 |
| 近亲基因惩罚 | -5（四项各减，再 clamp） | `inbreeding.genePenalty` |
| 近亲冷却 | ×(1+0.2) | `inbreeding.fertilityPenalty`（P-017） |

**本轮结果（1000 次）**

- 总体基因均值 56.5~56.9、标准差 8.5~9.1，与 founder 均值（约 60）方向一致。
- 近亲 vs 对照：基因均值低 5.0~5.2（hp 45.72 vs 50.94、atk 47.35 vs 52.58、
  def 41.44 vs 46.70、spd 48.11 vs 52.90），`genePenalty` 生效。
- 近亲突变率 0.055 vs 对照 0.044（+0.011，目标 +0.02；1000 样本下在噪声范围）。
- **近亲比例 0 的解释**：旧口径统计的是“随机 founder 配对”，founder 互不相关，必然为 0。
  现在拆成三个数：随机配对近亲率 0、构造近亲配对命中率 1、对照误判率 0，
  并验证子代 `ancestors` 已落库（是）。近亲实验真实有效。

## 6. 结论与仍不达标项

**通过**：五关胜率、平局率、平均回合数、技能密度、大招间隔、经济净产出、
7 天曲线（无 NaN/负值/封顶）、近亲基因惩罚；静态检查 12 项 0 失败 0 注意。

**仍不达标/需注意**

1. **第 1 关平均 3.70 回合**，低于 6；这是 core 快照锁定的 2 敌人教学关，整体 6.14 达标。
   若要求每关 ≥6，需要 A 放开 `buildEnemyTeam` 的 stage_1 快照断言后改成 3v3。
2. **小技能密度 0**：sim 策略攒大招；core 贪心 AI 则相反。两者都满足 P-002 的“不能每回合放”，
   但说明自动战斗缺少中间策略（见 §7）。
3. **第 2/4 关胜率偏低**（0.611 / 0.371），在 ±0.15 区间内但接近下沿；下一轮加样本/真实路径再看。
4. **近亲突变 +0.011** 未到 +0.02；1000 样本可接受，下一轮加到 5000 次复核。
5. **`hungerPenaltyWhenNoFoodPerHour` 暂为 0**：D-05 的 core 单测把示例配置当成“未配置”，
   填 >0 会导致 `advance.test` 失败（P-042 复发）。先填 0 保测试绿，见 §7.1。
6. **玩家等级是乐观假设**；真实玩家路径（不刷关）会更难，需要下一轮带重复次数的路径模拟。

## 7. 交接与变更请求（给 A / C）

### 7.1 需要 A 修的单测（阻塞项）

- **`advance.test.ts` D-05 用例**：`noFood(null)` 只设置 upkeep，没有删除配置里的
  `hungerPenaltyWhenNoFoodPerHour`；因此示例配置一旦按契约填 1.5，用例就失败。
  正确写法是显式 `delete habitatRow(...)['hungerPenaltyWhenNoFoodPerHour']`。
  修好后 D 会把值改为 **1.5**（当前为 0）。
- **`battle.test.ts` 伤害公式用例**：断言 `normal_strike` power=1.0 的伤害值（360/190/570/475）。
  D 无法在保持测试绿的同时下调普攻/水/土技能 power；本轮这些技能保持原值。
- **`determinism.test.ts` 固定种子快照**：`stage_1` 与它用到的水/土/fish_tide 技能被哈希锁定；
  任何数值调整都会让 `599747b4` 失配。建议改成“用固定 fixture 生成快照”，或把配置数值
  纳入快照更新流程；否则 D 每轮调参都要绕开这些技能。
- **`battle.test.ts` stage_1 敌人数量**：断言 `b0/b1`，导致第 1 关不能改 3v3。

### 7.2 需要 A 改的策略/接口

1. **自动战斗 AI 不会攒大招**：`autoCommand` 只选“可用技能里 power 最高”，45 能量就交小技能，
   几乎攒不到 70+。建议增加“留能量给大招”的自动策略（或做成可选），否则玩家开自动看不到大招；
   C 的异步 PvP 防守 AI 也受影响。
2. **`inheritance.weight` 未被消费**：DOMAIN §8.2 的特质突变是均匀抽取。
   若希望 epic 更稀有，建议按 weight 加权；或把 weight 改成“显性/隐性保留概率”并同步文档。
3. **`hit` 与 `statMods` 语义冲突**：`hit` 是加减、`statMods` 是乘数；特质/被动目前都不修 `hit`。
4. **PvE setup 入口**：`buildBattleSetup(teams)` 要求双方 `PetInstance[]`，
   sim 仍用 `buildBattleSetup([pets, pets]).teams[0]` 取玩家侧；建议提供单边入口。

### 7.3 需要 C 配合

1. **喂养/支出未模拟**：7 天曲线只含产出；真正闭环要等 C 把喂养、繁殖、升级支出接进服务端，
   用同一口径再跑。建议下一轮 D 提供“带玩家动作”的经济脚本。
2. **PvP 平衡**：本轮 fire/thunder/cat/snake 技能 power 下调、`grass_bloom` 治疗 20→60。
   异步 PvP 的胜率/时长需要 C 接入后用同一份配置复测。

## 8. 如何跑

